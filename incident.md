# Диагностика ошибки ENOSPC на корпоративном портале

## Возможная причина

Приложение не может записать данные. На файловой системе, куда оно пишет, могли закончиться свободные блоки или inode. Загрузка часто использует временный каталог и каталог документов. Ошибки 500 могут появляться и на страницах, где приложение сохраняет сессии, кэш или журналы. Сервер при этом может оставаться доступным.

## Проверки

Сначала сверю время первых ошибок и найду файловую операцию и путь в журнале приложения. Ниже пример для Linux с systemd. Имя сервиса и пути уточню по конфигурации портала. Для контейнера проверю путь из его окружения и соответствующий том на хосте.

```sh
journalctl -u portal.service --since '24 hours ago' -n 200 --no-pager
findmnt -T /path/to/uploads
df -h -- /path/to/uploads /path/to/temp
df -i -- /path/to/uploads /path/to/temp
```

Проверю каждый подтверждённый путь записи. Если файла ещё нет, использую ближайший существующий родительский каталог. По `findmnt` определю нужную точку монтирования. Следующие команды запускаются на ней с учётом нагрузки на рабочий сервер.

```sh
sudo du -x -h --max-depth=1 -- /mountpoint | sort -h
sudo du -x --inodes --max-depth=1 -- /mountpoint | sort -n
sudo lsof +L1
```

Первый вызов `du` помогает найти каталоги, занявшие место, второй — каталоги с большим количеством файлов. Если `df` показывает заполнение, а `du` не находит сопоставимого объёма, проверю вывод `lsof` на удалённые файлы, которые процессы всё ещё держат открытыми. Если в нужной файловой системе есть блоки и inode, перепроверю путь записи из окружения сервиса, лимиты тома и действующие квоты.

## Восстановление

1. Зафиксирую симптомы, результаты проверок и причину заполнения. Проверю наличие актуальной резервной копии перед изменениями, которые затрагивают рабочие данные.
2. Если том можно штатно расширить, согласую увеличение тома и файловой системы с администратором. Если место заняли журналы или временные файлы, применю штатную ротацию или очистку только к подтверждённо безопасным файлам по действующим правилам хранения. Рабочие документы, файлы базы данных и резервные копии сохраню.
3. Если место удерживает открытый удалённый журнал, определю процесс и переоткрою журнал штатным способом. При необходимости согласую перезапуск конкретного сервиса, учитывая активные операции пользователей.
4. Повторю `df -h` и `df -i`. Загружу и скачаю тестовый документ, проверю страницы с ошибкой 500 и свежие журналы. Проверю, что прежние документы доступны. Если есть признаки прерванных записей, отдельно сверю состояние затронутых операций.

## Профилактика

Настрою оповещения об остатке свободного места и inode на каждом используемом томе. Добавлю прогноз заполнения по темпу роста и проверку загрузки тестового документа. Настрою ротацию журналов с лимитами, срок жизни временных файлов и план расширения хранилища под рост объёма документов. Проверю, что резервные копии хранятся отдельно и из них можно восстановиться.

Справка по командам — [GNU Coreutils](https://www.gnu.org/software/coreutils/manual/coreutils.html), [systemd journalctl](https://www.freedesktop.org/software/systemd/man/latest/journalctl.html), [lsof](https://github.com/lsof-org/lsof/blob/master/Lsof.8).
